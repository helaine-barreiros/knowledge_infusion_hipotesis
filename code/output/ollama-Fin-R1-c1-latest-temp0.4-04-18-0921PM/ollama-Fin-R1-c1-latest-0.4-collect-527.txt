**Description:**
The PlantUML diagram represents the use case relationships within an AI-powered financial analysis and insights system. The main actors are **Client**, **Financial Advisor (FA)**, and **System Administrator (SA)**, each with their respective use cases.

1. **Clients**: Can view a financial dashboard (`CFR001`), receive alerts (`SFR002`), request predictions (`SFR003`), get recommendations (`SFR004`), manage preferences for recommendations (`SAFR002`), and send feedback (`CFR011`). They also have access to dashboards generated by the system (`SFR012`) and news relevant to their portfolios (`SFR013`).

2. **Financial Advisors**: Can manage mentoring sessions based on insights (`FAFR001`), view intervention alerts (`FAFR002`), analyze client predictive analytics (`FAFR003`), configure parameters for specific segments (`SAFR004`), and receive system-generated recommendations (`SFR015`, `SFR016`).

3. **System Administrator**: Manages AI analysis parameters to ensure compliance with regulations like Basel III (`SAFR001`). They also handle user feedback on the system’s outputs.

**Key Components:**
- The **AI Component (AIFR)** generates financial predictions, personalized recommendations, spending alerts, investment opportunities, and anomaly detection. These are requested by clients or advisors through specific use cases.
  
- **System Services (SFR)** include generating dashboards (`SFR012`), delivering contextualized news (`SFR013`), managing client interactions with the system via feedback (`CFR011`), and other operational services.

**Relationships:**
- Clients request financial data, alerts, predictions, recommendations, etc., directly from the AI or through system services.
- Advisors use generated insights to guide clients but also have their own set of requests (e.g., mentoring sessions).
- The SA configures parameters for compliance purposes and adjusts them as needed.

This structure ensures clarity in how different actors interact with the system’s components. Each use case is precisely mapped to its ID from the requirements, ensuring alignment.
