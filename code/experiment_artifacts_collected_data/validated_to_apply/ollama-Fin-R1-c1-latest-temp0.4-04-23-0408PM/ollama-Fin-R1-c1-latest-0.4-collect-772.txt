- **Client (c1)** interacts directly with the system via several use cases. They can view financial dashboards, receive alerts about transactions and spending limits, access personalized recommendations, etc.
- **SysAdmin (sa1)** manages analysis parameters related to AI components like `SAFR005` for generating spending limit alerts based on thresholds set by the system (`SFR004`).
- The **System** contains core functionalities such as financial prediction generation (`CFR003`), client alert creation (`SFR013`), and anomaly transaction detection (`AIFR006`). These are linked to their respective actors.
- The **AI System** handles more technical aspects like generating alerts, predictions, etc. For example, `AIFR006` generates anomaly transaction alerts which can trigger spending limit alerts managed by the system via `SAFR005`.
- Other systems (e.g., client management, financial advisor management) handle specific interactions and dashboards.

This structure ensures all actors and use cases are represented accurately with their relationships clearly defined. Relationships include direct actions (`-->`) for user requests and indirect ones through components like AI systems triggering alerts or generating insights based on data inputs. The system boundaries group related functionalities logically to maintain clarity in the diagram.
