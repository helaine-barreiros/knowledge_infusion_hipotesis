**Description of the Diagram Structure:**
- **Client**: Represents all client-related interactions (CFRs). They can view dashboards, receive alerts, make financial decisions based on recommendations and more. The system ensures these requests are handled through appropriate channels like notifications or direct data retrieval from AI components.
  
- **Financial Advisor**: Engages in mentoring clients using insights generated by the system, views intervention alerts for proactive assistance (e.g., when a client’s spending exceeds limits), reviews predictive analytics to tailor advice, and configures analysis parameters specific to their segments. These activities are supported by both human advisors and automated systems.

- **System Administrator**: Manages AI-related settings such as ensuring accuracy of algorithms through parameter adjustments or compliance checks with regulations like Basel III for risk management (SAFR001).

- **System Components**:
  - The main system (`Sys`) handles high-level operations including delivering alerts, personalizing recommendations, and generating dashboards.
  - The `AIFR` component contains AI-specific use cases: financial predictions, personalized recommendations, spending limit alerts via pattern recognition, investment opportunity analysis based on risk profiles.

- **Interactions**:
  - Clients interact directly with the system for viewing data or receiving recommendations. Financial advisors rely heavily on both human and automated components (e.g., using generated dashboards to inform clients).
  
This structure ensures clarity in how different actors use the system while maintaining logical groupings of related functionalities under their respective scopes. The inclusion of AI-driven features aligns with modern financial systems’ reliance on advanced analytics for decision-making support.

- Each actor’s role is clearly defined, and interactions are mapped to specific use cases.
- Inheritance relationships (e.g., SysAdmin managing analysis parameters) are indicated through the `<|--` notation in PlantUML.
