**Explanation of the Diagram Structure:**

- **Client Actor:** Represents users including clients, financial advisors, or system administrators. They interact with various use cases like viewing dashboards, receiving alerts, etc.
  
- **SysAdmin Actor:** Manages administrative tasks such as managing analysis parameters and client relationships.

- **FinancialAdvisor Actor:** Interacts with specific features related to mentoring sessions, client interactions, and predictive analytics.

- **System Boundary (Rectangle):** Contains the core functionalities of the system. Use cases within this boundary represent automated processes like generating alerts, predictions, etc., which are driven by inputs from actors or other use cases.
  
- **Use Case Relationships:** Arrows indicate actor-to-use-case relationships. For example, a client uses "View Financial Insights Dashboard" (CFR001), while the system generates spending limit alerts via "AIFR003."
  
- **Inheritance/Extends Relationship:** The SysAdmin role extends management over multiple use cases like CFR005 and SFR020 for historical records.
