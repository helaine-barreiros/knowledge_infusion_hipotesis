  - `Financial Advisor` (`fad`): Engages in client mentoring and receives specific insights from the AI.
  - `System Administrator` (`sa`): Manages analysis parameters for the AI to ensure compliance and accuracy.
- **Use Cases**:
  - Client-related use cases (e.g., viewing dashboards, alerts) are grouped under "Client".
  - Financial Advisor-specific actions like managing client interventions or configuring segments fall into their own category.
  - System Administrator tasks include parameter management (`SAFR001`).
  - AI-generated services (like recommendations, predictions, and anomaly detection) are categorized as `AIFR...`.
- **Relationships**:
  - The system uses cases like generating dashboards or alerts interact with the client through appropriate channels.
  - System administrators manage parameters that influence these interactions via the AI component (`SAFR001`).
  - Financial advisors receive and act on insights generated by the AI, such as predictive analytics for clients.

This structure ensures clarity in how different actors engage with system functionalities and how those services are delivered through inheritance or direct use. Each actor's role is distinct yet interconnected to form a cohesive financial advisory platform. 

### Key Observations:
- The `Client` interacts directly with most of the high-level features (dashboards, alerts), while advisors and administrators manage underlying parameters.
- Inheritance relationships (`<|--`) are used where one entity extends another’s capabilities or responsibilities, e.g., system components extending AI services for generating reports/alerts.
